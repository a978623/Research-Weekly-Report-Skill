# 周报篇幅与表达指南

## 默认成稿结构

用户要求写“一篇周报”时，同时交付两个部分：

```text
一、本周工作总结

二、下周工作安排
```

以用户最新确认的标题、样稿和提交口径为准。不要只写阅读计划，也不要把“本周做了什么”与“下周准备做什么”混在同一段。

没有另给篇幅时，可将全文约 1900—2400 个字符（包括英文论文题名）作为软预算，其中中文正文通常约 850—1250 字。英文长题名会明显增加总长度，不要误扩写成约 2000 字中文。优先贴近用户给出的样稿；材料少时不凑字数。

## 阅读工作怎样写

使用完整论文名称，保留原题名，不以缩写代替标题。标题较长时，一段完整写一次，后文可用“该工作”“该模型”或已说明的缩写。

每篇主论文通常用 3—5 句，按价值和材料多少灵活分配。较次要的论文可以更短，不要强行给每篇相同篇幅。段落应连起以下内容，但不要求四项逐条列出：

- **工作内容与机制**：作者处理了什么问题，关键模块或训练目标怎样发挥作用。
- **实际理解**：本次阅读弄清了什么，发现什么设计差异或证据边界。
- **课题价值**：具体能借鉴到哪一部分，例如序列融合、时间编码、图文检索或任务共享。
- **适用条件**：还缺哪些数据或验证，哪些结论不能直接迁移。

不要让整段只剩论文摘要，也不要把每篇都写成完整技术综述。只保留有助于解释课题启发的实现细节。讨论专家模型时应交代专家分工，讨论统一框架时应交代不同任务如何使用它，不能只写“采用了多模态融合”。

课题启发尽量写成具体问题或可比较的设计：例如先比较单序列表现，再判断附加序列的贡献；先比较时间表示，再决定是否增加融合模块。不要在没有结果时宣称某种模块已经改善性能。

## 完成状态必须分开

只依据用户确认或本轮可核对的材料描述进度：

| 状态 | 合适的表达 | 不可擅自升级为 |
| --- | --- | --- |
| 已阅读 | “阅读了……，重点理解……” | 已复现、已验证 |
| 只读摘要或部分章节 | “查阅了摘要”“初步了解……” | 已完整精读 |
| 讨论过的想法 | “目前的设想是……”“可以比较……” | 已完成模型设计或实验 |
| 计划阅读 | “下周计划阅读……，关注……” | 本周已完成阅读 |
| 已实现 | “完成了……的实现” | 方法有效、结果可靠 |
| 已有实验结果 | 描述实际比较、指标及范围 | 未测试场景中的普遍优势 |

模型能访问论文或笔记，不等于用户已经读过；计划清单中出现一篇论文，也不等于已读。用户已确认的完成情况不必反复质疑，但不能补造未提供的阅读感受、数据条件或实验结果。

## 语气与局部修改

采用适度正式、直白的中文，以自然成段为主。需要自己的判断时可使用“本次重点理解了”“对本课题而言”“目前的设想是”，但不要每段重复同一开头。

减少无具体内容的承接句，例如“进一步考虑”“奠定坚实基础”“具有重要意义”“提供新的思路”。这些词不是禁用词；若后面紧跟明确动作和对象，可以保留。判断标准是句子是否说明实际工作、具体用途或待验证的问题。

- “进一步探索多模态融合的潜力”过于空泛，可改写为“比较加入辅助序列前后的分类表现”。
- “为后续研究奠定基础”通常可以删除，或改成下一步真正要处理的问题。
- 用户希望以“对于本课题”起句时，可直接这样写，不必另加“通过阅读这篇文章，我进一步认为”。

用户只要求改一段、改一句或换一种说法时，只返回相应修改，不重写整篇，不引入新的阅读任务或技术主张。保留原有事实与完成状态。

## 下周安排怎样写

遵循用户最后确定的论文名单和数量。每篇写完整题名、主要阅读问题及对课题的用途即可；不把计划写成已经获得的结论。明确用户指定的文献时，不擅自换成自己偏好的论文。

需要推荐新论文、核对技术细节或回答“是否有人做过”时，另行核对原始论文。没有开展检索时，不写“尚无人研究”“首次提出”。

## 交付前快速检查

- 两个部分是否齐全，标题是否符合用户最新口径？
- 每篇是否有完整题名，是否说明机制和课题关系？
- 本周完成、讨论设想、下周计划和实验结论是否分清？
- 是否只写了实际材料支持的内容？
- 是否有可删除的套话，是否因英文题名而误判篇幅？
- 局部修改是否只改了用户指定范围？
